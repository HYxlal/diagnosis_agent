    ### 2 电驱诊断Agent标准输入

电驱诊断Agent的标准输入是用于向诊断系统提供必要信息以进行故障诊断的结构化数据，主要采用JSON格式。其核心目的是确保Agent能够准确理解用户问题并结合上下文进行推理。

#### 2.1 通用入参结构体
该结构体包含多个字段，分为必填和可选：

```json
{​
    // 基础通用字段（必填）​
    "raw_query": "用户原始提问文本",​
    "mcuid": "MCU_001",​
    //可选字段：意图识别名称和置信度，平台agent输出​
    "intent_name": "DTC故障码解读"​
    "query_confidence": 0.96, ​
    // 抽取实体（平台NLP识别输出，字典，无实体为空对象）​
    "entities": {​
    "dtc_code": ["U162483","P1A3E98"],​
    "project": "H37A",​
    "component": "IGBT/MCU",​
    "working_condition": "爬坡满载、低温冷启动",​
    "software_version": "H37A3621830AW"},​
    // 多轮对话上下文​
    "session_id": "M20260727001",​
    "context_history": [​
        {"query":"上一轮用户提问","entities":{"dtc_code":["P1A3E98"]},"agent_answer":"上一轮诊断结果"}],// ​
     //辅助业务字段（可选）​
     "user_id": "XX"​
     }​
```

#### 2.1.1 字段说明
1. **核心依赖字段**：`raw_query`（原始问题）和 `entities`（抽取实体）是Agent推理的核心依据，缺失会导致诊断准确度大幅下降。
2. **多轮对话支持**：`session_id` 和 `context_history` 用于维护对话上下文，实现连续问诊（如用户补充信息后继续诊断）和知识沉淀（记录历史诊断过程）。
3. **实体处理规则**：若某实体无对应内容，需传空数组（如 `"dtc_code": []`）或空对象（如 `"entities": {}`），不存在的字段无需传递。


### 3 电驱Agent标准输出数据

Agent的标准输出是对输入问题的诊断结果，同样采用JSON格式，包含状态码、消息及输入引用信息。

#### 3 标准输出数据示例
```json
{​
    "code": 0, ​
    "msg": "诊断推理完成",// 回显平台输入信息​
    "input_ref": {​
        "raw_query": "MCU报P1A3E98爬坡IGBT过温",​
        "intent_id": "MCU_001",​
        "entities": {"dtc_code":["P1A3E98"]}​
     },​
 // 核心诊断输出​
    "diagnosis_result": {​
        "fault_root_cause": ["冷却油泵流量不足","IGBT散热基板积灰","高温标定阈值偏激进"],​
        "fault_trigger_condition": "满载爬坡、环境温度＞35℃",​
        "classification": "功率器件热故障",​
        "solution": ["1 读取EOP油泵实际转速信号校验","2 拆解水道清理冷却回路杂质","3 临时上调IGBT高温保护标定阈值（仅临时方案）"​
        ],​
        "risk_warning": "V1",​
        "maintenance_suggestions"："更换前电子泵"​
        "similar_cases"："历史案例XXX"​
      },​
 // 辅助参考信息​
     "reference_material": ["电驱故障排查FTA","历史案例XXX"],​
     // 多轮对话标识​
     "need_multi_round": true, // true代表需要追问用户补充信息​
     "follow_up_question": "是否采集过油泵实时转速曲线？",​
     "diagnosis_confidence": 0.92 // 本次诊断结论置信度​
     }
```

#### 3.1 状态码规范（`code`字段含义）
状态码用于指示诊断过程的状态：
- **0**：正常返回，Agent成功生成完整诊断结论（如故障原因、解决方案等）。
- **-1**：入参缺失关键信息，导致无法进行诊断（例如缺少必要的故障码 `dtc_code` 或项目信息 `project`）。
- **-2**：Agent内部推理过程出现异常（如算法错误、数据处理失败等）。
- **-3**：识别到问题不属于电驱系统范畴，因此不执行电驱诊断流程（例如用户询问的是电池或底盘问题）。


### 总结
- **输入**：通过结构化的JSON数据提供用户问题、实体信息及上下文，确保Agent获取足够的诊断依据。
- **输出**：通过状态码和诊断结果反馈，明确诊断状态（成功/失败/异常）及具体结论，同时引用输入信息以保证一致性。这一机制保障了电驱诊断系统的标准化交互和可靠性。
